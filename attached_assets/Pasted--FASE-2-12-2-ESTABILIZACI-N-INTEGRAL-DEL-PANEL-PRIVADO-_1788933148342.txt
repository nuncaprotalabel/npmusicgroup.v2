# FASE 2.12.2 — ESTABILIZACIÓN INTEGRAL DEL PANEL PRIVADO

## OBJETIVO

Corregir de forma definitiva la navegación, el funcionamiento de Solicitudes, la navegación BACK/FORWARD y la traducción completa del panel privado.

El panel privado debe funcionar como una aplicación moderna:

CLICK → NAVEGACIÓN → CONTENIDO CORRECTO

sin necesidad de actualizar manualmente la página.

Esta fase tiene prioridad sobre cualquier nueva funcionalidad.

NO iniciar Fase 2.13.

NO continuar todavía con la validación E2E de ARTIST.

NO reconstruir el proyecto.

NO cambiar la arquitectura general.

NO instalar dependencias nuevas salvo que sea absolutamente imprescindible.

NO utilizar `window.location.reload()` como solución a problemas de navegación.

NO crear datos ficticios permanentes.

---

# PARTE A — NAVEGACIÓN DEL PANEL PRIVADO

## PROBLEMA ACTUAL

Actualmente algunos apartados del panel privado solo muestran correctamente su contenido después de actualizar manualmente la página.

Ejemplo:

1. Entrar al panel.
2. Hacer click en "Artistas".
3. La navegación no carga correctamente.
4. Al actualizar la página, "Artistas" aparece correctamente.

Esto ocurre también en otros apartados.

DEBE CORREGIRSE LA CAUSA REAL.

Inspeccionar únicamente:

* layouts privados;
* sidebar desktop;
* sidebar/mobile;
* header;

* navegación de `/admin`;
* navegación de `/np-control`;

Buscar específicamente:

* navegación manual incorrecta;
* `router.push()` mal utilizado;
* `preventDefault()` bloqueando enlaces;
* overlays invisibles capturando clicks;
* elementos con `pointer-events`;
* botones dentro de enlaces;

* componentes que dependen incorrectamente de `window.location`;
* providers que mantienen estado obsoleto;
* problemas de layout anidado;
* problemas con Server Components / Client Components;
* rutas que necesitan refresh para ejecutar correctamente;
* redirects incorrectos;
* links apuntando a rutas antiguas;
* componentes reutilizados con estado stale;
* condiciones basadas en pathname que no reaccionan a navegación client-side.

NO modificar archivos que no estén relacionados con este problema.

# 3. ACTIVE STATE

* el sidebar debe reflejar la ruta actual;

Verificar rutas anidadas.

`/admin/lanzamientos/123`

`/admin/lanzamientos/123`

→ `/admin/artistas`

No depender de un refresh.

No crear loops de navegación.

No enviar al usuario accidentalmente al sitio público.
